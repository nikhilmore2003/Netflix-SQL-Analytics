Database schema

Three tables joined on show_id. Before analysis I cleaned the data: blank directors and countries became NULL, missing ratings became “Not rated”, missing durations became “Unknown”, and date strings were converted to real dates.

netflix

8,807 rows · content details
  • show_id PK
  • type text
  • title text
  • director text
  • cast text
  • country text
  • date_added date
  • release_year int
  • rating text
  • duration text
  • listed_in text
  • description text

netflix_content_costs

8,807 rows · money
  • show_id FK
  • type text
  • production_cost_million_usd int
  • marketing_cost_million_usd int
  • estimated_revenue_million_usd int

netflix_viewership

8,807 rows · audience
  • show_id FK
  • type text
  • release_year int
  • total_views_millions int
  • avg_watch_time_minutes int
  • peak_region text

SQL skills shown

🧹

Data cleaning

UPDATE statements to standardise blanks into NULL or default labels before analysis, so counts and filters are accurate.

🔗

Joins across tables

Content, cost and viewership tables joined on show_id to answer questions about profit and audience.

🪜

Window functions

ROW_NUMBER() OVER (PARTITION BY …) to find the top rating and the top 3 most profitable titles within each type.

🧩

CTEs & subqueries

Multi-step logic split into readable CTEs, including a recursive CTE that splits comma-separated cast lists.

🔤

String & date functions

Pulled minutes and seasons out of text durations, matched patterns with LIKE, and filtered on date ranges.

💡

Business insight

Each query answers a real question, like where content comes from, what's profitable and which region watches most.
